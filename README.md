# charlemagne

A Go CLI that generates resttest-shaped services from embedded
[`text/template`](https://pkg.go.dev/text/template) files, driven by a service
catalog in [pax-utah-cfg](https://github.com/benthinnick/pax-utah-cfg)
(`charlemagne.json`). The first template set is **health-only** HTTP:
`/healthz`, `/readyz`, `/metrics`. Application RPCs are gRPC, generated by
`charlemagne build`. Postgres services also get an [ent](https://entgo.io)
scaffold; table schemas are owned by the service, not the catalog.

## Usage

```bash
go run ./cmd/charlemagne new demo
go run ./cmd/charlemagne new demo --config /path/to/charlemagne.json
go run ./cmd/charlemagne build users
go run ./cmd/charlemagne build users --stage orm
go run ./cmd/charlemagne build users --from rpc
go run ./cmd/charlemagne build users --config /path/to/charlemagne.json
```

`new` looks up the name in the catalog and writes `./<name>/` (fails if that
directory exists and is not empty). Module path: `github.com/benthinnick/<name>`.

`build` requires that `./<name>/` already exists. It runs these stages (print
`==> name` as they run):

1. `proto` — merge catalog `endpoints.grpc` into `pax-utah-cfg/proto/services/<name>/<name>.proto` (empty request/response stubs; existing fields are kept)
2. `protobuf` — `buf generate` into `./<name>/internal/proto`
3. `rpc` — entity types, the usecase `RPC` interface, gRPC server wiring, and missing usecase stubs
4. `orm` — if the service has `postgresql`, ensure `internal/ent` exists; if `internal/ent/schema/*.go` is present, `go generate ./internal/ent` and wire `Providers.Ent`
5. `tidy` — `go mod tidy`

`--stage NAME` runs one stage. `--from NAME` runs that stage through the end.

Edit proto messages, then run `build` again. Usecase implementation files are
not overwritten. Add ent schemas under `internal/ent/schema/` (owned by the
service), then `charlemagne build <name> --stage orm`.

Build needs `buf`, `protoc-gen-go`, and `protoc-gen-go-grpc` on `PATH`:

```bash
go install github.com/bufbuild/buf/cmd/buf@latest
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
```

Catalog path resolution:

1. `--config`
2. `CHARLEMAGNE_CONFIG`
3. `../pax-utah-cfg/charlemagne.json` relative to the current directory

Each service has `name`, `id` (`SERVICE_ID` in the generated app),
`dependencies`, and optional `endpoints.grpc`. Known dependencies: `postgresql`
(alias `postgres`) and `vault`. Omitted deps are not wired into the generated
service.

After `new`, Charlemagne runs `go mod tidy` and, when Postgres is a
dependency, `go generate ./internal/providers`. After `build` it runs the
`tidy` stage.

## Development

```bash
make test TESTFLAGS=
make vet
go run ./cmd/charlemagne new demo --config ../pax-utah-cfg/charlemagne.json
```

Templates live in [`templates/health`](templates/health) and are compiled into
the binary.
